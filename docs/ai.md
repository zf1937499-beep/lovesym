# AI 模块

用小米 MiMo 的 OpenAI 兼容接口做五件小事：润色、约会策划、日记草稿、出题、月总结。
所有调用都在服务端，浏览器只跟自家的 `/api/ai/*` 打交道。

## 1. 文件与调用链

```
ai.mjs              aiComplete / aiJSON / 清洗 / 额度 / Key（仅服务端）
ai-features.mjs     五个功能的 system prompt + 结果整形
server.mjs          路由 /api/ai/{polish,date,diary,quiz,monthly} + /api/ai/usage
assets/ai.js        浏览器端封装（post / busy / failMessage）
```

```
浏览器 ──POST /api/ai/polish──▶ Node ──OpenAI SDK──▶ api.xiaomimimo.com/v1
          （不带 Key）                    （Key 只在服务端）
```

`aiComplete(system, user, { maxTokens, temperature, maxChars })` 是唯一出口：
拼 messages → 调用 → 清洗 → 截断。`aiJSON` 在其上加了容错解析（模型偶尔会带解释文字）。

## 2. 五个功能

| 功能 | 入口 | 输入 | 输出 |
|---|---|---|---|
| 润色 | 日记编辑器底部 | 草稿 + 语气（温柔/俏皮/真诚） | 三个版本，点「用这个」替换草稿，**不保存** |
| 约会策划 | 愿望页「✨ AI 策划约会」 | 城市 / 人均预算 / 偏好标签 | 3~4 个节点，可一键转成愿望待办 |
| 日记草稿 | 日记页「✨ 根据今天生成草稿」 | 天气 + 今日打卡 + 最近照片备注 | 100~200 字草稿进编辑器，**不保存** |
| 出题 | 小宇宙 → 默契问答 | 昵称 + 愿望关键词（只传前 8 个字） | 5 道题 + 每题「出题理由」 |
| 月总结 | 小宇宙 → 本月报告 | 当月统计数字 | ~150 字，手动点「保存到月报」才落库 |

## 3. system prompt 的三条底线

每个 prompt 都写了同一条约束的三层：

1. **只改表达**：「只能调整措辞、语序、节奏，不得改变原意，不得增删事实」
2. **不越界**：「不评判这段关系，不给建议，不说教」
3. **去套话**：「不写祝福语、不写『继续加油』『未来可期』」

反例约束也写死了，比如约会策划要求「禁止『感受当地氛围』这类空话」，
月总结要求「必须引用输入里的具体数字，不要编造数据」。

## 4. 失败降级

| 情况 | 表现 |
|---|---|
| 服务端没启动 / 断网 | 按钮文案不变，点完 toast「连不上服务，AI 功能先歇一会儿」，原功能照常 |
| 上游 401 | 「AI 密钥无效，检查一下服务端配置」 |
| 上游 402 | 「AI 账户余额不足，充值后就能用了」 |
| 上游 429 | 「AI 调用太频繁，等一会儿再试」 |
| 返回不是 JSON | 走文本兜底（按编号/换行切分），再不行提示「这次没给出可用版本」 |
| 输出过长 | 统一 `sanitize` 截断：润色 500 字、草稿 400 字、月总结 220 字 |
| 页面没加载 ai.js | 按钮禁用并显示「AI 未连接」 |

所有调用各自 try/catch，**不会阻塞页面渲染**——页面先正常渲染，AI 只是附加按钮。

## 5. 额度

```js
const DAILY_TOTAL = 40;
const DAILY_BY_KIND = { polish: 15, date: 8, diary: 10, quiz: 5, monthly: 6 };
```

- 记在 `data/ai-usage.json`，按天重置；
- **先扣额度再调用**，失败也算一次，避免刷接口；
- 超限返回 429，前端提示「今天的 AI 额度用完了」。

实测：`quiz` 连发 6 次 → 5 次通过、第 6 次拦截。

## 6. 验收清单

| # | 项目 | 结果 |
|---|---|---|
| 1 | MiMo 接口调用正常 | ⚠️ 网络与鉴权通过（返回 402 而非 401），但**账户余额为 0**，需充值后才能出内容 |
| 2 | 无 AI 时功能可用 | ✅ 编辑器、愿望、报告全部正常；按钮给出友好提示，不阻塞 |
| 3 | Key 不暴露 | ✅ 浏览器只请求 `/api/ai/*`；响应与前端代码中都没有 Key |
| 4 | 输出长度可控 | ✅ `sanitize` 截断生效（300 字传 50 → 50 字）；月总结 >220 字自动截断 |
| 5 | 额度限制 | ✅ 单功能 5/5 后拦截；总量 40/天 |
| 6 | 输出清洗 | ✅ 去掉 ``` 围栏、去掉「好的，这是…」开场、压缩空行 |
| 7 | 不自动保存 | ✅ 润色只替换文本框，草稿只在编辑器里，月总结要点「保存」才入库 |

## 7. 换 Key / 换模型

改 `ai.mjs` 顶部三行即可：

```js
const MIMO_API_KEY = "…";
const MIMO_BASE_URL = "https://api.xiaomimimo.com/v1";
const MIMO_MODEL = "mimo-v2.6-flash"; // 复杂任务可换 pro
```

## 8. 安全提醒

- Key 是硬编码在 `ai.mjs` 里的（按需求），**这个文件不要提交到公开仓库**，也不要截图外发；
- 一旦泄露，去控制台吊销重发，然后只改这一行；
- 部署时确保 `node_modules` 和 `data/` 不进版本库（`data/` 里是你们的真实日记和照片）。
